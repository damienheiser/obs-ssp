# Native SSP stream selection and media framing

The operator authorized direct camera tests and coordination with the camera agent. The production native serializer previously placed stream style in the enable field and left the selector zero. It now writes enable=1 followed by the requested selector. Video/audio parsers remove only the observed bounded twenty-byte extension and retain legacy media bodies. This changes native connector framing, not camera settings, authentication or the packed plugin IPC contract. The boundary is packet serialization and length-checked parsing; malformed recognized extensions never reach media callbacks. The existing four-MiB packet allocation bound remains unchanged.

Tests first reproduced the serializer mismatch, then exercised actual production functions using a local socketpair and private real camera video/audio packets. Captured extensions, their truncations and legacy media without extensions are covered. Real six-second native captures returned distinct main4096x2160HEVC/PCM and secondary1920x1012AVC/AAC feeds with microsecond PTS deltas. Extracted media is private and excluded from git. External FFmpeg decoded both video streams and both audio formats without errors. The actual plugin decoder harness decoded177/177HEVC10bit frames in software and160/160AVC8bit frames through VideoToolbox; this does not substitute for a live OBS-source test. Three focused CMake checks passed. Other physical camera models and platforms are untested.

Recovery: revert the focused native protocol commit or restore the prior connector binary; no firmware or camera settings changed.
